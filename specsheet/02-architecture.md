## 4. Architecture

The product is `rust-src/`, a cargo workspace with three members: `cli` (the shipped binary, crate name ytdlp-cli), `harness` (the differential dispatcher that drives the same functions against the reference; dev-only, never shipped) and `fake-ytdlp` (the scripted yt-dlp stand-in; dev-only, never shipped). One binary per platform, split into modules along seven layers (term, config, resolve, args, exec, update, ui; layer names followed by the specsheet citations in code comments). The layer boundaries are the constraint that matters; the module count is an implementation detail.

| capability | windows | posix |
|---|---|---|
| raw keys, echo, kbhit | the CRT `_getwch`/`_kbhit` pair via FFI (tty.rs) | termios raw mode ported flag for flag (tty.rs) |
| VT enable | SetConsoleMode ENABLE_VIRTUAL_TERMINAL_PROCESSING via windows-sys | not needed |
| shell folders | HKCU Shell Folders registry read via windows-sys (resolve.rs) | XDG user-dirs, then HOME |
| folder dialog | SHBrowseForFolderW via windows-sys (menu.rs) | zenity/kdialog shell-out |
| clipboard read | the Win32 clipboard, CF_UNICODETEXT via windows-sys (clipboard.rs) | the first of wl-paste/xclip/xsel/pbpaste on PATH that answers |
| terminal size | GetConsoleScreenBufferInfoW srWindow rect | TIOCGWINSZ; any error reads as no room (`block_under_input`) |
| process tree kill | taskkill /F /T | killpg SIGKILL |
| sha256 | hand-rolled, streaming, NIST vectors pinned (sha256.rs) | same |
| json | hand-rolled for the settings schema (settings_json.rs) | same |
| rng | hand-rolled PCG32 (rng.rs) | same |
| east-asian + printable tables | hand-rolled pinned tables (width_table.rs, printable_table.rs) | same |
| http + tls | ureq + rustls + webpki-roots (net.rs) | same |
| zip / tar.xz | zip / tar + lzma-rust2 (archive.rs) | same |
| charset safety | 9-pair map + ascii replace (`ascii_safe`, term.rs); decode policy per site | same |

Crate policy (owner decision): minimal vetted set. A crate is permitted only where std genuinely lacks the capability and hand-rolling would be a security liability - TLS and HTTP being the clear case. sha256, JSON, the RNG and the east-asian width table are hand-rolled because they are small, auditable and testable offline. No TUI crate and no terminal framework: the menu stays a hand-rolled ANSI box over the reader seams, per the owner's no-special-frontend rule. Current dependencies: ureq 3.4.2, zip 7.2.0, tar 0.4.46, lzma-rust2 0.15.8; windows-sys 0.61 (windows target), winresource 0.1 (windows build).

Language-specific rules that are gates rather than style, recorded so they are auditable: writers are wrapped in a BufWriter once outside every loop with an explicit flush before drop and write_all; interactive stdout is locked per frame and flushed after every frame and before every blocking read; hot loops allocate no format! / clone / to_string per iteration and reserve known sizes; the release profile sets overflow-checks = true so an arbitrary-precision assumption panics instead of silently wrapping; decoding is explicit at every byte boundary, per site (the download and http pipes decode UTF-8 with replacement; subprocess helper reads use the locale encoding; settings reads are strict UTF-8 into the settings-unreadable branch), and no byte-offset slicing assumes ASCII; no bare unwrap, every former exception path is a tested Result branch. Rationale and sources: recorded in the section 4 decision record and the CHANGELOG chapters.

G8 evidence landed (2026-10-15): (1) the non-forced ceiling measured against the unroutable RFC1918 address 10.255.255.1:9 in WSL - the shipping port's `timeout_global` elapsed 6.01 s and answers `timeout: global`; the port keeps the measurement as the `#[ignore]`d `net.rs::timeout_ceiling_is_six_seconds_against_a_black_holed_host`, not as a CI-hanging assert. (2) The loopback fake proxy is dialed: with HTTP_PROXY set the production impl sends `CONNECT example.invalid:80 HTTP/1.1` (ureq tunnels plain http transport through CONNECT where the reference sends an absolute-form GET - the dial is the parity, the framing is recorded), and a full tunnelled transfer lands the body bytes on disk. (3) `fake-ytdlp` speaks `-U`: it answers with yt-dlp's wording, replaces its own image (the same rename-over move a real self-update makes, so a post-update probe is a fresh spawn and not a memo hit - the probe memo keys on `(path, mtime)`, audit F4), and reports the new version from then on; a whole `--update` round runs offline with the session transcripts matching the reference's (the pre-check probe, the child's own `Latest version:` / `yt-dlp is up to date (...)` output inherited, the post-check probe reading the new version, `  cli`) and the cli half refused through a closed loopback proxy - the port prints the refusal line with the seam's word exclusion (`io: Connection refused (os error 111)`), which is the shape the decision record gates. (4) The no-changes guarantees are unit tests in the cli crate: a wrong published digest leaves `.new`, `.new.part` and the image untouched, a truncated archive reports unreadable and writes nothing, an unrunnable build is probed exactly three times with two one-second sleeps and installed nowhere.

The selftest keeps the injection discipline instead of patching module state - every subcall takes its seams (Io out+reader, World flags, closures) from a `SelftestWorld` built by the selftest, and recordings follow the same shapes the crate tests and the harness arms established (scripted `Reader` queues, recording `Out` sink, scripted fetch/time/selftest-gate closures). Where a check targets a native equivalent that has no call hook to patch, the check is recorded as a named deviation in the conformance map (section 10): `act 9 is multi url` drives `act("9")` for real and asserts the multi-url screen bytes plus the non-repaint outcome; `item 12 leaves the save to main_menu` asserts the settings file bytes are untouched by the `act("12")` round (the type system already forbids a save inside `act`); the cli update check pins the releases-api source (`RELEASES_API` is the FR-13 contract); the two `install_cli` write checks stage the dance on a scratch side-name pair (`<copy>` plus `<copy>.new`, the staged copy carrying the running image's bytes) because no check ever renames the running image, and the `<new> --selftest` gate is scripted 0/2 at the dance, since a live-spawned gate would recurse (a shipped `--selftest` run genuinely installing its copy would spawn a nested selftest whose own dance spawns again); the gate's REAL spawn path is pinned by the crate's named unit test plus one live two-image dance at a real tagged release (ran at v2.0.0, OQ-N4).

Runtime liveness rules for the packaged run: the probe-memo check and the probe-shim check spawn real child processes (a `.bat` shim on windows, `.sh` on posix; the rc 2880417800 rejection spelling included; the memo probe drives a second, guaranteed-answer shim because there is no portable interpreter call to borrow), scratch fixtures live in fresh `mkdtemp` dirs that are removed at the end of every path, the settings file is only read (bytes compared before and after; nothing written), the history/LineEdit checks run against a fresh `History` so process state is untouched, and the whole report prints through the production `Out` so windows' newline translation behaves like every other output path.

Build matrix. One target per published platform, no fallback target: a broken build fails CI rather than producing a different binary. Linux builds in WSL (the linux line additionally builds `x86_64-unknown-linux-musl` for the musl bundle, FR-19 - statically linked, so the same bytes run on glibc and musl hosts; bundles.yml builds it and run-proves it on the ubuntu runner); Windows builds in GitHub Actions because the Windows SDK import libraries are absent from the dev environment and `lld-link` cannot substitute for them - the compiler is not the missing piece, the SDK is; macOS builds in GitHub Actions (macos-latest, arm64) and has published macos artifacts since v2.1.0 (owner calls 2026-10-17g/h/k: lean+portable first, portable-only after the lean mac bundle was pulled, pkg instead of the tar bundle since v2.2.0 - FR-18). The Windows build uses host target x86_64-pc-windows-msvc with the NFR-1 crt-static flag, and `cli/build.rs` attaches the PE version resource (FR-16) through the `winresource` build-dependency - windows builds only, build-time only.

Data ownership: settings.json is the single source of truth for user defaults; the product owns it exclusively. Known language codes are a pinned source reference, not a setting (args.rs). All 16 schema fields, types, defaults, validation and code sites are listed in the Data section.

Third-party and licensing: the CLI invokes yt-dlp and ffmpeg as separate processes. This is aggregation per the FSF GPL FAQ, so the MIT CLI and the GPL-2.0-or-later ffmpeg binaries in the portable bundles and the mac pkg keep separate licenses (THIRD-PARTY-NOTICES.md lines 4-25). The linux-musl bundle ships no third-party binary at all (FR-19): yt-dlp and ffmpeg there are the system's own. ffmpeg versions shipped: windows gyan.dev 9.0.2 essentials (sha256 60f467265b1e312373dbcd92200c2618a74850f98d3d078e94296bb3fa2047ba), linux BtbN n9.0.2-27-g7e93014c5b-20261013 (sha256 50e0ede136e3545758a8dfb2e6cd12ec865643cd138af9ce6cd36a9015f395c2, the dated autobuild-2026-10-13 tag; the moving latest tag republished its asset and the v1.5.0 line recorded that digest, but the dated archive's ffmpeg binary is byte-identical to the v1.5.0-shipped binary, sha256 a573011f38a3022b051b2960e232164821e0be986d6d3c6d6a5a2ece369e549a, probe 2026-10-16) (lines 32-44). macos joins at v2.1.0 (owner call 2026-10-17g): shaka-project/static-ffmpeg-binaries n8.1.2-1, asset ffmpeg-osx-arm64, sha256 e7b9fcd97f95f333512d6e8b8ac24d9dbc08f189f36047695499bd7b57214b22 (34,074,040 bytes, verified 2026-10-17), the same GPL line. The pinned yt-dlp source shows yt-dlp itself does not bundle ffmpeg and writes its own speed fields as >10s (bundled reference read 2026-10-13, cited in change history for the width rules).

Alternatives and decisions (record): console background control was tried and reverted by user call (CHANGELOG v1.2 "navy background reverted"); console resize was implemented and reverted (v1.1); the old single-stage download line was replaced by the stage/spinner design (v1.2 "staged download flow"); subtitle work moved from the video run to a separate pass after 429 aborts killed downloads (FR-9 rationale); ffprobe was deleted after its last consumers were removed (non-goals); the release files ship one tag rather than per-platform releases: five bundles since v2.3.0 (windows and linux lean+portable each, plus the linux-musl cli bundle - FR-19), the windows per-user setup.exe and the macos-arm64 pkg (FR-18; the mac tar bundle was retired by owner call 2026-10-17k) plus the attached RELEASE-NOTES.md (README asset table; the bare-binary updater assets FR-13 defined were pulled from the release by owner call 2026-10-17j).
