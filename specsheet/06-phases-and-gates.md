NATIVE LINE, gate 0. The native product (`rust-src/`) was specified before any native code was written, so every later gate has a fixed reference to be measured against. The twelve phases and eleven gates, as executed, are recorded in this section's evidence trail and the CHANGELOG chapters. One rule binds the line: no functional requirement may be added, removed or altered without a recorded decision and owner approval - where the implementation cannot be literal it is recorded as a decision (FR-13 self-update, FR-14 windows source, the section 4 decision record) rather than left implicit. The gate structure per native release replaces gate 2 and gate 3 equivalents: a differential parity gate, then a bundle-extracted-and-run gate on each target platform.

G9 (phase 9, the packaged selftest) is specified as: the shipped build answers `--selftest` with the full check set ported natively (same names, same order, same count, rc 0 when all pass and rc 1 otherwise), verified by a report-vs-report compare against the oracle's stream rather than only by cargo tests; the conformance map (every check name, native predicate and named rename) is recorded in section 10; the self-install dance runs on a scratch side-name pair with a scripted
gate by construction, and the live `<new> --selftest` gate proof was deferred to the first tagged release (OQ-N4, closed at v2.0.0).
