## 4. Native decision record (section 4 continuation, per phase)

NATIVE DECISIONS recorded during phase 2: integers are i64 throughout - a settings value or version piece beyond it saturates at the i64 bound instead of arbitrary precision (no real yt-dlp or youtube value approaches that, and the differential protocol itself carries i64 only; pinned by rust tests); numeric pattern matching over yt-dlp or user input is ASCII (the unicode digit classes are not ported - yt-dlp emits ASCII digits, and the harness protocol cannot carry the rest); `pick_checksum` splits checksum files on `\n` (published files are LF/CRLF); float rendering reproduces the oracle's `repr` semantics (`py_float_repr`, pinned against probed oracle values) because the coercion path renders through it and the settings writer needs the same rendering.

NATIVE DECISIONS recorded during phase 3 (state layer): the settings-file codec reproduces the oracle's `json` as the settings file sees it - floats parse as floats, `NaN`/`Infinity`/`-Infinity` parse as non-finite floats and are written back with those exact spellings while finite floats keep `repr` semantics; the writer emits `json.dumps(s, indent=2, sort_keys=True)` plus one LF with `ensure_ascii=True` escaping (short forms and `\uXXXX` for 0x00-0x1f, `\uXXXX` for 0x7f and every char above, astral chars as surrogate pairs); integers saturate at i64, so a bignum in a settings file is the one divergence the differential protocol cannot carry - pinned by rust tests instead; duplicate keys are last-wins; a lone-surrogate `\u` escape maps to U+FFFD, recorded - the oracle keeps the lone surrogate; the read path applies universal-newline translation (CRLF and lone CR to LF) for both the load parse and the `save_settings` skip-compare, and the loader never writes; a settings file whose JSON is not an object carries typed error branches and the harness compares port-domain shape tokens (`unreadable`, `type_error`, `attribute_error`, `not_utf8`) because payloads are shape-gated. `not_utf8` is the invalid-UTF-8 case in the save compare, while every other read failure falls through to the write.
