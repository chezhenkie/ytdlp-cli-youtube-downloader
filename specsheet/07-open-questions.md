OQ-P1 (owner report 2026-10-17; harness session 2026-10-17b, full record in scratch-oqp1/OQ-P1-REPRO-SESSION.md): the resident yt-dlp process was NOT reproduced. A scripted harness launched the key0-ci build (3873840 - the build the owner tested) in a real console window (direct conhost.exe launch; key and ctrl injection validated against a CRT probe) with a loopback-only slow download: menu quit, escape mid-download, and a real X-close (WM_SYSCOMMAND/SC_CLOSE) all ran clean - the app killed the yt-dlp tree, exited, left no survivor at exit or +8s, and bin\yt-dlp.exe stayed deletable. The Ctrl+C path was exercised as CTRL_BREAK: a true Ctrl+C keypress is not injectable (GenerateConsoleCtrlEvent CTRL_C does not deliver to console clients, CTRL_BREAK does; SendInput needs the foreground) and the app's handler is ctrl-type agnostic, so the app-side path is identical. Not tested: closing a Windows-Terminal-style pseudo console mid-download (the Win11 default-terminal form of "closing the app"; conpty-run.exe carries the compiled-but-unused close directive) and the download-completion-then-quit path. Two candidate vectors from code review, both unreproduced: (1) spawn_version_probe's 60s timeout kills only the direct child (the PyInstaller bootloader), so the python child can be orphaned and keep the exe locked - hardening (shipped in v2.0.3) taskkills the tree like exec/run.rs kill_tree_real; (2) a sub-millisecond spawn race against a taskkill /T enumeration. Closed 2026-10-17b with the v2.0.3 release: vector (1) shipped hardened (the probe timeout now kills the whole tree - CHANGELOG v2.0.3, test a_probe_timeout_kills_the_whole_tree), per the owner call to release any successful hardening as v2.0.3; vector (2) stays unproven; the untested pseudo-console close path (ClosePseudoConsole) stays documented in the session record should a report ever recur.
