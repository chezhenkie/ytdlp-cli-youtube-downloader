NATIVE PORT, gate 0. A second product line, `app-rust/`, is planned to implement this same specification natively. Gate 0 is this amendment: the spec is written before any native code, so every later gate has a fixed reference to be measured against. RUST-PORT-PLAN.md carries the twelve phases and eleven gates. Two rules bind the port and are stated here rather than only in the plan: the Python implementation remains shipped and supported until the owner's cutover, and no functional requirement
may be added, removed or altered by the port - the native product must do exactly what this document specifies, and where the port cannot be literal it is recorded as a decision (FR-13 self-update) rather than left implicit. The port's own gate structure replaces gate 2 and gate 3 equivalents per native release: a differential parity gate, then a bundle-extracted-and-run gate on each target platform.
